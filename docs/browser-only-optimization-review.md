## 1. 上传身份、正文边界与落盘事务

完成内容：

- 删除跨刷新 `localStorage` 上传恢复。重新选择文件始终生成新 upload ID，不能再仅凭文件名、大小和 `lastModified` 把另一份内容接到旧暂存文件后；
- 保留同一页面、同一 `File` 对象的失败重试：先用 HEAD 核对服务端持久化 offset，再用 PATCH 续传；
- 服务端要求 PUT/PATCH 声明总长度和精确 offset，最多写入本次声明的剩余字节，并继续检查正文确实结束；额外正文返回 `413`；
- 在读取最终长度前执行 Tokio `flush`，避免异步文件写队列尚未完成时偶发把正确上传误判为 `409`；
- 完整提交顺序固定为：等待写队列、`sync_all` 暂存文件、同目录原子 rename、`fsync` 父目录，全部成功后才返回 `2xx`；
- 上传超时、磁盘水位不足、连接取消和强制停止分别保存有效检查点或删除无效暂存，不提前覆盖旧目标。

主要验证：

- 单元测试覆盖超长正文、正文空闲/总超时、磁盘预留计算和提交阶段故障注入；
- Playwright 用“相同名称、大小、mtime，不同内容”的旧 localStorage 记录验证页面使用新 ID 完整 PUT；
- 真实半包 HTTP 上传持续到 30 秒停机宽限结束，force token 触发后验证 20 MiB 检查点已经持久化且最终目标尚未出现。

## 2. 根 fd、符号链接别名与并发写协调

完成内容：

- `RootedFs` 在启动时长期打开共享根，并要求 Linux `openat2`；
- 路由 metadata、直接列表、递归搜索、ZIP 条目发现和内部维护扫描全部从该根 fd 使用 `openat2`/`*at`，不再通过启动路径字符串重新发现文件；
- 目录展示的名称、类型和 metadata 来自同一次 fd 锚定枚举；绝对链接和根外链接在发现阶段即不可见；
- 维护任务只删除从原根 fd 发现、在父目录 fd 下再次操作的严格内部名称；
- 路径协调器同时比较词法路径和由目录设备号/inode 构成的语义键；真实路径与根内相对符号链接别名不能并发修改同一对象；
- 租约等待期间只要协调版本变化就重新解析全部语义键，并在插入租约前原子核对版本；符号链接从 A 改指 B 时不会沿用指向 A 的过期键；
- 活跃上传暂存使用“父目录设备号/inode + 内部文件名”登记，维护任务从真实路径发现文件时也能识别经根内别名发起的上传；
- 删除根目录、原子不覆盖 move、上传覆盖和目录创建继续使用父目录 fd 及 Linux 原子操作。

主要验证：

- 运行中把共享根重命名并在原路径创建替换目录，列表、下载和维护仍只作用于启动时打开的原根；
- 单元测试覆盖符号链接别名与真实路径的同对象租约冲突，以及互不相关兄弟路径仍可并行；
- 根外、绝对和根内相对符号链接集成测试保持通过；悬空或成环的根内相对链接可以列出并由 DELETE/PUT 管理，GET 不会跟随无效目标。

## 3. 统一资源预算

完成内容：

- 所有监听器共享活跃连接上限，默认 256；
- HTTP/1 请求头读取限时 10 秒，最大缓冲 64 KiB；
- 普通请求处理并生成响应头默认限时 300 秒；文件、Range 和已生成 ZIP 的正文传输不属于该时限，由连接上限和外部网关的正文/空闲超时约束；
- 上传具有单文件大小、正文空闲时间、总时间、并发数和最低剩余磁盘空间限制；
- 搜索具有并发数、遍历项数和运行时间限制；
- ZIP 具有并发数、遍历项数、按实际读取字节计算的未压缩总量、临时归档实际输出量、运行时间和私有临时文件边界；
- 上传与 ZIP 共用按 Linux `st_dev` 分桶的磁盘空间追踪器；上传按声明剩余量预留，ZIP 每次写入临时归档前增量预留当前缓冲，设备号相同的两类操作在同一锁内完成 `fstatvfs`、检查和记账，不同文件系统互不误拒；
- ZIP 异步写入处于 `Pending` 时预留继续有效；上传每次实际写入前重新核对“最低保留空间 + 当前文件系统全部预留”，已完成的实际写入先由文件系统可用空间反映，再释放对应预留；
- 列表/搜索、ZIP、上传使用 `try_acquire`，满载时返回明确的 `429`；上传或 ZIP 超限、超时和空间不足分别返回 `413`、`408`/`504`、`507`；
- permit、空间预留、文件和路径租约通过所有权 guard 在完成、错误或取消时释放；ZIP 并发 permit 持续到响应正文发送完成或被丢弃。

该联合记账封闭了 Dufs 进程内部上传与 ZIP 的检查后并发写竞态。外部进程、宿主机对 virtiofs 导出目录的直接写入以及存储侧异步空间变化不受本进程锁控制，仍可能在最后一次检查后竞争空间；部署时仍应保留合理水位并监控底层文件系统。

配置项和默认值集中在 `Args`，命令行与 YAML 都使用同一严格校验；零并发、零响应准备时限、不一致的上传时限以及超过 Tokio 信号量上限的并发配置都会阻止启动。

## 4. 大目录、遍历、排序、Range 与 MIME

完成内容：

- 目录 HTML 只包含页面上下文和 CSRF，不再注入完整目录 JSON/Base64；
- 受认证的 list API 默认返回 200 项，最大 500 项，并支持 `sort`、`order`、`q` 和不透明 cursor；
- cursor 绑定目录设备号、inode、纳秒级 mtime/ctime 和查询条件；Dufs 内目录项结构变化返回 `409`。外部进程对现有子文件的原地内容、权限或时间修改不改变父目录时间，不属于游标检测和进程内协调保证；
- 直接目录枚举只保留当前页所需的 `limit + 1` 个候选，不创建完整目录 `Vec`；
- 名称小写排序键在构造条目时只分配一次，并以原始名称形成确定的最终次序；
- 搜索和 ZIP 的同步文件系统遍历进入受跟踪的 blocking 任务，并通过有界 channel 传递条目；
- 单段 Range 会把超出文件末尾的 end 截断，超长 suffix 返回完整文件，多段仍返回 `416`；构建只允许 64 位 Linux，消除 32 位长度截断边界；
- 已知二进制扩展名不再读取内容样本，只有未知或文本类型执行最多 1024 字节的文本/字符集探测。

主要验证：

- 1205 个新增文件以 37 项分页，断言无重复、无遗漏且顺序稳定；
- cursor 的目录项结构变化和排序条件不匹配分别返回 `409`、`400`；
- 提供默认忽略的 100000 项真实目录基准测试；本轮手工验收中第一页约 2.63 秒完成，该数值只记录本机结果，不作为跨设备性能承诺；
- Range 覆盖空文件、超长 suffix、超出末尾、非法倒序和溢出数字；
- MIME 回归覆盖已知二进制、未知二进制和文本。

## 5. 有界异步日志

完成内容：

- 文件、stdout 和 stderr 共用容量 4096 的同步有界 channel 与独立写线程；
- HTTP 访问日志在动态字段拼接阶段就使用 16 KiB 有界构造器，重复变量不会先形成巨型临时字符串；全部日志在入队前再执行同上限的 UTF-8 安全截断并带唯一固定标记；
- 自定义格式最多 4096 字节和 128 个解析元素，配置超限会阻止启动；
- 请求线程只执行非阻塞 `try_send`，慢磁盘或日志接收端不会直接卡住 Tokio worker；
- 写线程批量写入并每 250 ms flush，不再逐行强制刷新；
- 队列满时丢弃最新记录，运行中至多每秒输出一次聚合 `dropped_newest` 告警；显式 flush 和退出仍报告尚未输出的累计数；
- 正常停止的 flush 最多等待 5 秒，不会无限挂起；
- URI、用户名、普通请求头、handler 错误和连接错误都经过单行控制字符转义；
- Authorization、Proxy-Authorization、Cookie 和 CSRF 请求头继续统一脱敏。

## 6. 现代桌面浏览器前端

完成内容：

- 动态文件名、路径、用户和错误只通过 `textContent`、属性 API、`URL` 和 `DocumentFragment` 进入 DOM；禁止 `innerHTML`、`insertAdjacentHTML` 等动态 HTML 接口；
- 上传、新建、移动、删除、加载更多、取消和注销使用原生按钮、中文可访问名称、可见焦点和 `aria-live` 状态；
- 所有用户可见界面、状态、提示和错误统一为中文；
- 生产脚本不引入打包器，拆分为 `api.js`、`path.js`、`dom.js`、`listing.js`、`operations.js`、`upload.js`、`app.js`；
- 上传队列支持进度、速度、剩余时间、重试、取消、认证暂停和顺序恢复；
- 拖放仅被阻止触发浏览器导航，不再构成上传入口；
- `Permissions-Policy` 在登录页和目录页统一关闭相机、麦克风、地理位置、支付和 USB；
- Playwright 启动器动态分配端口，Chromium 与 Firefox 为必需矩阵，正式 Edge 为可选明确矩阵。

## 7. Argon2id 账号策略

完成内容：

- 账号只接受完整 Argon2id PHC，不接受明文、其他算法或旧格式兼容分支；
- 固定 PHC 版本 `v=19`、`m=19456`、`t=2`、`p=1`、16 字节 salt 和 32 字节输出；
- `hash-password` 生成与启动校验使用同一策略；
- 配置端与浏览器登录端复用 128 字节用户名上限；重复、空或超长用户名，空哈希、异常参数和格式错误都会阻止启动，错误不回显账号或凭据；
- 最多两个 Argon2 校验 blocking 任务并发，permit 持续到计算真正结束。

## 8. Rust 分层与存储可测试性

完成内容：

- 增加 `lib.rs`，服务实现可由进程入口和进程内测试共同使用；
- `main.rs` 只负责配置、监听、连接生命周期和 Linux 信号；
- `server.rs` 负责请求边界与路由，具体职责位于 session、browser_api、listing、download、upload、rooted_fs、storage 等子模块；
- `RequestContext` 在 HTTP 边界统一保存 peer 和访问日志上下文，认证成功后才写入用户名；
- `AppError` 分离公开状态/消息与内部诊断来源，500 响应不暴露文件系统细节；
- `StorageDurability` 把最终上传的文件同步和原子发布从 HTTP handler 注入，测试可确定性地令每个阶段失败；
- 关键 blocking 工作通过 `TaskTracker` 登记，停机和请求取消不会留下失去所有权的后台文件操作。
